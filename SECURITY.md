# Security Policy

## Supported Versions

| Version | Supported             |
| ------- | --------------------- |
| 0.x     | ✅ Active development |

## Reporting a Vulnerability

ReviewLume takes security and privacy seriously. If you discover a security vulnerability within this project, **do not** open a public GitHub issue or discussion.

Use GitHub's private vulnerability reporting flow from the repository **Security** tab and choose **Report a vulnerability**. If that option is not available, contact the repository maintainer through their GitHub profile and request a private reporting channel before sharing technical details.

Please include:

- The affected version or commit.
- Reproduction steps or a minimal proof of concept.
- The expected impact.
- Any suggested mitigation, if available.

Never include a real Runtime API Key, local MCP token, Authorization header, customer source code, private repository content, production secret, raw verification output, or raw payload in an initial report.

## What to Expect

- We will acknowledge receipt within 48 hours when possible.
- We will provide an estimated timeline for a fix and coordinated disclosure.
- We will notify the reporter when the issue is resolved and published.

## Scope

The following are considered in scope:

- VS Code extension vulnerabilities.
- Git command injection through malicious repository names, paths, refs, or content.
- Unauthorized file-system access outside the selected repository.
- Bypasses of `.git`, absolute-path, parent-traversal, symlink, binary, file-size, request-size, result-size, or rate-limit boundaries.
- Exposure of ignored or sensitive files in a way that contradicts the documented MCP behavior.
- SecretScanner or export-gate bypasses in the separate P8 Advanced Review Pack workflow.
- Local MCP authentication, Origin, content-type, lifecycle, cancellation, and residual-access failures.
- Secure MCP Tunnel configuration, proxy isolation, credential leakage, or unsafe subprocess invocation.
- Unexpected MCP write, shell, terminal, patch, delete, Git mutation, or process-start capabilities.
- Local verification approval bypasses, repository-binding bypasses, command or argument substitution, shell invocation, runner symlink escapes, approval-fingerprint bypasses, or execution in an untrusted workspace.
- Local verification timeout, cancellation, child-process-tree termination, stale-result, workspace-fingerprint, output-bound, ANSI-control, or secret-redaction failures.
- Repository content, diffs, search terms, search results, verification output, Runtime API Keys, local MCP tokens, or Authorization headers entering ReviewLume diagnostic logs.
- Residual access after a connection is stopped or VS Code exits.

The following are **out of scope** unless ReviewLume introduces or amplifies the issue:

- Social engineering of project contributors.
- Attacks requiring physical access to the developer's machine.
- Vulnerabilities in OpenAI, ChatGPT, VS Code, Git, browsers, operating-system URL handlers, test runners, or other third-party services.
- Exposure caused solely by a user intentionally connecting a repository that contains sensitive data, when ReviewLume behaves according to the documented MCP read boundaries.
- Side effects intentionally performed by repository test code or its dependencies after the user approved the disclosed local verification rule, unless ReviewLume exceeded the approved executable, arguments, repository, timeout, or environment boundary.
- Incorrect or unsafe recommendations generated by ChatGPT when ReviewLume has not executed or applied them.

## Privacy and Data Flow

ReviewLume keeps the ChatGPT-facing MCP connector read-only and locally controlled, but a connected repository and local verification output are not automatically secret-filtered:

- ReviewLume does not provide MCP tools for shell, terminal, process start, file write, file delete, patch application, or Git mutation.
- One active MCP connection is bound to one explicitly selected Git repository.
- The local MCP listens only on a random `127.0.0.1` port and uses a fresh high-entropy token for each run.
- The OpenAI Runtime API Key is stored only in VS Code SecretStorage and is not written to the repository, settings JSON, command arguments, clipboard, or logs.
- Absolute paths, parent traversal, `.git`, external symlink targets, directories, binary files, and oversized file reads are rejected.
- Result sizes, file counts, request sizes, concurrency, and call rates are bounded.
- MCP tool calls do **not** automatically run SecretScanner and do not automatically block `.env`, credentials, secrets, private-key text, production configuration, or tracked sensitive files.
- `read_file` can read an explicitly addressed regular text file inside the repository, including an ignored file, when the caller knows or guesses the path.
- Diffs, file excerpts, commit subjects, search results, test target paths, and verification output may contain secrets or personal data.
- ReviewLume does not collect telemetry.
- When the user enables the ReviewLume app or connector in ChatGPT and asks a project question, ChatGPT may request repository metadata, content, or completed verification evidence through the OpenAI Secure MCP Tunnel. Returned results leave the local machine and are processed by OpenAI under the user's OpenAI account and applicable terms, workspace controls, and privacy settings.
- ReviewLume does not read browser cookies, sessions, passwords, browsing history, or ChatGPT responses.
- P8 Advanced review history and exported Review Packs remain local unless the user deliberately sends or copies them elsewhere. P8 has its own SecretScanner and export gates; those controls do not automatically apply to MCP or local verification output.

## Local Verification Execution Boundary

The optional local verification assistant is not an MCP action tool and is not a general terminal.

The approved boundary is:

- Trusted Workspace only.
- One canonical Git repository per approval.
- A fixed executable, fixed argument prefix, fixed target mode, and fixed timeout shown in a modal approval UI.
- Repository-local runner entry points discovered only from fixed supported locations.
- `spawn(executable, argv)` with `shell: false`.
- No package-script execution, no `npx`, no runner download, no free-form command strings, and no instructions taken from AI responses, repository files, or process output.
- Relevant configuration or runner changes invalidate the approval.
- Newly added or modified matching test files can be appended automatically as argv targets without changing the approved execution rule.
- A reduced environment, bounded output, best-effort redaction, timeout, cancellation, and process-tree termination.
- A result fingerprint covering HEAD, staged and unstaged diffs, and non-ignored untracked state; mismatched evidence is reported as stale.
- Approval and results stored in VS Code extension storage rather than in the repository.

Tests remain executable untrusted repository code and can have side effects. ReviewLume detects repository changes during a run but does not sandbox the runner, network, database, local services, or child-process behavior.

The two MCP evidence tools—`verification_status` and `read_verification_output`—can only read completed stored evidence and explicitly report that MCP cannot start processes.

Users must remove, rotate, or redact real credentials; inspect the approved verification rules; use isolated test resources when necessary; and avoid connecting repositories or verification output they are not authorized to provide to OpenAI.
